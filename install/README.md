# Install scripts

This folder installs the Learning Agents pack into another AI-agent workspace.

The installer copies the reusable pack into `.learning-agents/` in the target workspace, seeds a `learner_records/` skeleton, and writes provider-specific context files for OpenAI-compatible agents, Claude agents, Gemini, and Google Antigravity.

The two implementations (`install_learning_agents.sh` and `.ps1`) both read their generated file contents from `install/templates/`, so they cannot drift apart. **Edit the templates, not the scripts.**

## Quick install

From this repository, run one of:

```bash
install/install_openai.sh --target /path/to/your/workspace
install/install_claude.sh --target /path/to/your/workspace
install/install_gemini.sh --target /path/to/your/workspace
install/install_antigravity.sh --target /path/to/your/workspace
```

Or install all provider integrations:

```bash
install/install_learning_agents.sh --provider all --target /path/to/your/workspace
```

On Windows PowerShell, use:

```powershell
pwsh install/install_learning_agents.ps1 -Provider all -Target C:\path\to\your\workspace
```

## Provider outputs

Every provider gets `.learning-agents/` (pedagogy, agents, prompts, schemas, examples, templates) and a seeded `learner_records/`. On top of that:

| Provider | Additional files in target workspace |
| --- | --- |
| OpenAI-compatible agents | `AGENTS.md` |
| Claude agents | `CLAUDE.md`, plus `.claude/` — skills, subagents, commands, and the SessionStart/Stop hooks |
| Gemini | `GEMINI.md`, `.gemini/settings.json` |
| Google Antigravity | `GEMINI.md`, `.gemini/settings.json`, `.antigravity/workflows/learning-agents.md` |

### The seeded learner archive

```
learner_records/
├── profile.md      goals, baseline, calibration preferences
├── roadmap.md      curriculum state, rolled up from the ledger
├── mastery.md      per-node × per-aspect evidence, located edges, misconceptions
├── deck.md         flashcards with spaced-repetition due dates
├── drills/         speed and repetition sheets
├── resources/      per-module reading lists
└── sessions/       one log per session, each ending in a Next Session Entry Point
```

This is what makes the system a course rather than a series of unrelated lessons. The orchestrator's first instruction is to load it, so without it a fresh install boots into a broken requirement.

## Safety behavior

- The `.learning-agents/` pack is refreshed on every install. Do not edit it in place — edits there are destroyed on the next run.
- **`learner_records/` is never overwritten.** Each file is seeded only if absent, so reinstalling over a live course is safe. `--force` does not override this.
- An existing `.claude/settings.json` is left alone rather than merged; the installer prints the source path so hooks can be merged by hand.
- Existing provider files are backed up before replacement unless they were already generated by this installer (detected via a `learning-agents:generated` marker).
- Use `--force` to overwrite generated provider files. Note that `--force` destroys hand edits to those files without a backup.

## After installation

Ask your agent tool to read its provider context file — and to read `.learning-agents/pedagogy/README.md`, which holds the method the agents bind to. Then provide a learner request with:

- topic
- target outcome
- current level
- deadline or time horizon
- weekly time budget
- preferred formats
- constraints

Example request:

```text
Use the installed Learning Agents pack.
Topic: cloud security
Target outcome: prepare for an entry-level cloud security role
Current level: basic Linux and networking
Time budget: 8 hours/week for 4 months
Preferred format: hands-on labs and docs
Create diagnostics, curriculum, resources, projects, and progress checks.
```
